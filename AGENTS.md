# AGENTS.md

Conventions for coding agents working in this repository. Humans follow the same rules; this file
is the condensed version. The reasoning behind each rule lives in docs/adr. The current state of
the work, the pitfalls already hit and the suggested next steps are in docs/handoff.md.

A migration to bounded-context modules and new transports is under way:
docs/plans/ddd-transports/plan.md, in phases, with ADR-0015 to ADR-0024. Until a phase lands, the
layout, commands and workflow below describe the code as it is; each line changes in the commit
that makes the new one true.

## Project

- tigerbeetle-platform: a Go API in front of TigerBeetle with Postgres for metadata, a React
  console that only talks to the API, and later a posting-rule DSL. Pre-alpha.
- TigerBeetle is the only source of truth for money. Postgres never stores a balance.
- Describe the project as a platform for working with TigerBeetle. Never present it as a clone
  of, or compatible with, another ledger product.

## Layout

- `apps/api`: Go module `github.com/wilfriedago/tigerbeetle-platform/apps/api`.
  - `cmd/api/main.go`: entrypoint. `internal/bootstrap` wires everything by hand and runs the
    servers and workers. No DI framework, no globals, no `init()`.
  - `internal/kernel/ledger`: the shared kernel, pure types and rules, no I/O imports.
  - `internal/modules/<module>`: one bounded context each, in layers `domain` (rules, the ports
    infrastructure implements), `application` (commands and queries, exported as interfaces in
    `usecases.go`; `ports.go` declares what it needs from other modules), `infrastructure`
    (Postgres with its own sqlc queries in `postgres/queries`, TigerBeetle) and `interfaces`
    (`dto`, `rest/v1`). `ledgers`: ledgers, account rules, event types. `bookkeeping`: accounts,
    transactions, holds, write requests, the overview, the reconciler. `health`: liveness,
    readiness and service information, an interfaces layer only. Generated code (sqlc) is in
    `gen` subpackages, committed, excluded from lint, never edited.
  - `internal/transport/rest` is the one list of REST operations, served by bootstrap.
  - `internal/platform`: config, logging, HTTP server lifecycle, the Postgres pool and the
    TigerBeetle client of the process, readiness probes, the Huma REST builder (`restapi`), the
    transport-neutral problem mapping, wire scalars and request IDs.
  - `migrations/` (goose, embedded, one sequence), `sqlc.yaml` (one block per module).
    `cmd/openapi` writes the spec.
- `packages/openapi/openapi.yaml` is the contract, generated from the Go registrations by
  `cmd/openapi`; never edit it. `packages/api-client` is the orval client generated from it
  (`src/gen`, one module per tag, never edited) over a hand-written fetch layer in `src/client`
  (ADR-0019). `deploy/compose` is the local stack.
- `apps/console`: React console on TanStack Router, Query, Form, Table and Pacer (ADR-0014).
  - `src/routes`: thin file routes (search schema, loader, crumb). `src/route-tree.gen.ts` is
    generated by `just generate`, committed, never edited.
  - `src/features/<slice>`: `api.ts` (query options, mutations) and the slice's pages.
  - `src/components/ui`: shadcn base-nova components restyled with the design tokens; edit them
    in place. `src/components/ledger`: amounts, addresses, IDs, chains, balances.
  - `src/lib`: money (bigint only), time, preflight, validation, the API client.

## Dependency rules (enforced by golangci-lint depguard)

- The kernel (`internal/kernel/ledger`) imports nothing from `internal`.
- A module's `domain` imports only the kernel. `application` imports its domain and the kernel,
  never `platform`, a driver or a transport. `infrastructure` implements domain ports and may use
  `platform`; `interfaces` call use cases, never infrastructure or a driver.
- Modules never import each other: a module declares what it needs from another in
  `application/ports.go`, and `internal/bootstrap` passes the other module's query to it.
- `platform` holds no business rule and imports no module; the transports and bootstrap compose
  modules, never the reverse. `cmd/openapi` builds without drivers or cgo.
- Every rule has a fixture in `apps/api/testdata/depguard`; `just lint-depguard-probe` proves each
  one fires. Add a fixture with a new rule or module.
- No packages named `utils`, `common` or `helpers`. Name packages by what they provide.

## Go rules

- Standard library first: `net/http` with Go 1.22+ patterns, `log/slog` JSON, `testing` with
  `go-cmp`. No web framework except Huma on the ServeMux for REST (ADR-0018), no assertion
  library.
- `context.Context` is the first parameter of anything doing I/O.
- Errors: typed domain errors (`ledger.ErrNotFound`, `ErrAlreadyExists`, `ErrInvalid`,
  `ErrUnavailable`), wrapped with `%w`, checked with `errors.Is` and `errors.As`. The HTTP adapter
  maps them to RFC 9457 `application/problem+json`. Never leak TigerBeetle or Postgres error text
  to clients.
- `GET /healthz` is liveness only. `GET /readyz` probes Postgres and TigerBeetle with a short
  timeout and reports each one.
- Tests: table-driven unit tests next to the code; integration tests behind the `integration`
  build tag with testcontainers; everything runs with `-race`.
- Format with gofumpt and goimports (`just format`). Lint with `just lint` before committing.
- Explain non-obvious choices in a short comment or an ADR, not in chat.

## TypeScript rules

- Vite+ is the toolchain (ADR-0011): `vp check` formats (Oxfmt), lints (Oxlint) and type-checks.
  Its settings live only in the root `vite.config.ts`; do not add `fmt` or `lint` blocks to
  package configs. Run it through pnpm (`pnpm exec vp check`); `just lint` and `just format`
  include it.
- `vp dev`, `vp build` and `vp test` are built-ins; `vp run <task>` runs a package script. Use
  the `just` recipes, which go through Turborepo for TypeScript.
- Import from `vite-plus` and `vite-plus/test` in config and test files, not `vite` or `vitest`.
- Git hooks are Vite+ (ADR-0012): `.githooks/` scripts plus the `staged` block in the root
  `vite.config.ts`, whose Go and spec entries call just recipes. Add new pre-commit checks there,
  not in a separate hook tool.
- Console: amounts are integer strings and bigint, never `number`. Colours come from the
  tokens in `src/styles/globals.css`, never raw values. URL state goes in the route's search
  schema. Writes use `useIdempotencyKey` and renew the key only after a final answer.
- Adding a console page: a route file, a page in its feature folder, query options in the
  feature's `api.ts` calling the generated client functions; run `just generate`. List filters
  go through `queryParams`; money writes pass their key as the typed `Idempotency-Key` header.

## TigerBeetle rules

- IDs come from the client's `ID()` helper (time-ordered), never from hashing. Convert with
  `modules/bookkeeping/infrastructure/tigerbeetle/id.go` when storing in a uuid column
  (big-endian).
- Source is the debit account, destination the credit account, balance is credits minus debits.
- One API transaction is one linked chain; `user_data_128` carries the transaction ID; `code`
  carries the business event type.
- The Go client version must not exceed the server image version. Bump both together;
  `scripts/check-versions.sh` enforces it.

## Workflow

- Every task is a `just` recipe at the root (ADR-0016); `just --list` shows them.
  `scripts/install-tools.sh` installs just and the Go tools at their pinned versions.
- Adding an endpoint: implement the use case in the owning module, register the operation with
  its input and output structs in the module's `interfaces/rest/v1`, run `just generate` (spec,
  then client), add tests. Commit all of it together; CONTRIBUTING.md lists the steps.
- Conventional Commits, small commits, each leaving `just lint`, `just test`, `just build` green.
- `just generate` must produce no diff on a clean tree (`just generate-check`, which CI runs).
- Pin everything: Go modules, npm packages, Docker tags, GitHub Actions by SHA, tool binaries in
  `scripts/install-tools.sh`.
- No emojis anywhere. SQL keywords uppercase, identifiers lowercase. `.editorconfig` applies.
- Out of scope until decided otherwise: authentication, release pipelines, Kubernetes.
- An ADR whose status reads `Accepted, amended by ADR-NNNN` is partly replaced: read the amending
  ADRs before acting on it. A new ADR that replaces part of an older one sets that status line in
  the same commit (ADR-0015).
- When instructions conflict or a tool behaves unexpectedly, stop and ask rather than guess.
